# adabay 0.1.0 (2026-07-07)

Initial public release. Implements a semi-simulation framework for the rapid evaluation and calibration of Bayesian group sequential designs (GSDs) across four endpoint types: continuous (normal-normal or normal-inverse-gamma updates), binary (beta-binomial), count (gamma-Poisson) and time-to-event (gamma-exponential).

## Public API

* Constructors: `set_design()`, `set_prior()`, `set_decision()`, `set_accrual()`.
  * `set_design()`'s sample-size and exposure schedules are specified **pooled across both arms** and split into per-arm targets by `allocation_ratio`: for `n_per_look` (continuous/binary), `n_c[k] = round(n_per_look[k] / (1 + allocation_ratio))` and `n_t[k] = n_per_look[k] - n_c[k]`; `exposure_per_look` (count) splits the same way without rounding; survival is specified directly in pooled event counts (`d_per_look`/`d_total`). This gives one consistent look-schedule convention across all four endpoints. The number of looks is inferred from the length of the per-look vector; an empty vector, or a schedule whose per-arm split would not be strictly increasing, is rejected with an informative error.
  * `set_accrual()`'s `rate` is the **pooled** (both-arms) recruitment rate, split into per-arm rates by the design's `allocation_ratio` (`rate_c = rate / (1 + allocation_ratio)`, `rate_t = rate_c * allocation_ratio`). `allocation_ratio` applies to all four endpoints, including survival. Time-to-event designs simulate staggered Poisson patient entry rather than treating recruitment as instantaneous, so the calendar-time exposure cutoff at each event-driven look is driven by the simulated arrival times; an accrual specification is therefore mandatory for survival endpoints.
* Non-conjugate prior workflow: `fit_mixture()` approximates a user-specified prior by a finite mixture of conjugate components with per-quantile tail-probability diagnostics, and returns an `adabay_prior_arm` object that plugs into `set_prior()` via its `arms` argument. When the (suggested) RBesT package is unavailable, the internal EM fallback grows the number of components up to `n_components_max` until the maximum tail-probability error is within `tol_tail`, rather than stopping at the forward-KL elbow (forward KL is mass-covering, not tail-accurate). `fit_mixture()` accepts a `seed` argument for reproducible internal sampling when `prior` is supplied as a density function, and `print()` lists each fitted component's weight and conjugate parameters.
* Entry points: `evaluate_design()` is the single polymorphic entry point for obtaining operating characteristics. Passing an `adabay_design` runs the fused simulate-and-aggregate path for a one-off single-design evaluation; passing an `adabay_cache` (built once by `build_cache()`) aggregates pre-computed per-look tail probabilities cheaply. `calibrate_design()` sweeps a threshold grid against the cached path for the caching API of Section 6 of the manuscript; its `$best` element is an `adabay_calibration_best` object carrying the selected thresholds together with `type_I` (from the H0 cache) and `power`/`expected_sample_size` (from the H1 cache), each explicitly labelled, plus the full `oc_h0`/`oc_h1` objects for further inspection. On the effect scales evaluated by fixed-node Gauss--Legendre quadrature (`"risk_difference"`, `"risk_ratio"`, `"odds_ratio"` for binary and `"rate_difference"` for count), `evaluate_design()` and `build_cache()` warn when a prior shape below 1 could make the per-look tail probability inaccurate, and point to a shape-at-least-1 prior or a closed-form relative-effect scale.
* Methods: `print()` and `summary()` for `adabay_oc`; `plot()` for `adabay_oc` (per-look stopping-probability fan plot) and `adabay_prior_arm` (density overlay with tail-quantile rugs).

## Reproducibility

* Parallel execution via `parallel::mclapply` on POSIX and `parallel::parLapply` on Windows, with L'Ecuyer combined multiple-recursive generator for per-worker streams.
* Within-cores bit-identical reproducibility at any fixed `(seed, cores)` pair.
* Cross-cores bit-identical reproducibility via the `cross_core_reproducible` argument on `evaluate_design()` (fused path) and `build_cache()`. When `TRUE`, the simulator pass runs in a single driver process regardless of `cores`, giving simulator output that is bit-identical across worker counts; the posterior and aggregation passes are already core-independent. The default is `FALSE`.
* For time-to-event designs, `expected_duration` is the direct Monte Carlo mean, across simulated trials, of the calendar time realised at each trial's own stopping look (read from the simulated recruitment timeline). Continuous, binary and count designs use an analytic expected-duration formula.

## Documentation and scripts

* Three `knitr` vignettes (`overview`, `evaluation`, `calibration`), each covering both conjugate and non-conjugate prior scenarios where applicable.
* Per-endpoint self-contained scripts in `inst/examples/`: `transform2.R` (continuous, TRANSFORM-2 esketamine for treatment-resistant depression), `adrenal.R` (binary, ADRENAL re-design), `bnt162b2.R` (count, Pfizer--BioNTech BNT162b2 COVID-19 vaccine trial), `checkmate141.R` (time-to-event, CheckMate-141 head and neck cancer trial).
* A single standalone replication script (`replication.R`), distributed alongside the package tarball in the manuscript's `Code/` directory, that reproduces every numerical result in the manuscript under a single `RUN_FULL_PRECISION` configuration flag, with comparator-package calls (BATSS, adaptr, gsbDesign) guarded by `requireNamespace()`.

## Tests

* `testthat`-based suite covering each constructor, the mixture fitter and its tail-probability diagnostics, the per-look posterior path for each of the four endpoints against an analytic symmetric-null benchmark, the equivalence of cached versus direct evaluation at the same threshold combination, the cross-cores bit-identity guarantee for `cross_core_reproducible = TRUE`, and the staggered Poisson recruitment path for time-to-event designs (including the mandatory-accrual contract), and a guard test that the fixed-node quadrature scales warn when a prior shape falls below 1. 59 `test_that` blocks and 203 passing expectations.
