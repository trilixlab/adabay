BNT162b2 vaccine re-design (count endpoint)

Five-look Bayesian GSD on the log-rate-ratio scale. Section 5.3 of the manuscript.

Setting

The Pfizer–BioNTech BNT162b2 trial (Polack et al., NEJM 2020;383:2603–2615) was a phase II/III randomised, observer-blinded, placebo-controlled vaccine-efficacy study in adults of two doses of the BNT162b2 mRNA vaccine against placebo (saline) for the prevention of laboratory-confirmed COVID-19 with onset at least seven days after the second dose. The primary analysis was performed under a Bayesian group sequential framework on the cumulative number of confirmed cases across arms, with four planned interim analyses at 32, 62, 92 and 120 accrued cases and a final analysis at 164 cases. The protocol was powered to detect a vaccine efficacy VE > 30% (rate ratio Δ* = λt / λc < 0.70) under a design alternative of VE = 60% (rate ratio 0.40), with a placebo background incidence rate of approximately λc = 0.018 cases per person-year. Case events under a homogeneous Poisson process in each arm satisfy the gamma–Poisson conjugate pair exactly, so the strict Poisson model implemented by adabay is the natural design-stage idealisation.

Bayesian GSD re-design

We re-implement the BNT162b2 design as a five-look Bayesian GSD (K = 5) with looks placed at the cumulative person-time at which each prespecified case-count milestone is expected to fire under H1. Under λ-bar = (λc + λt) / 2 ≈ 0.0126 per person-year at the designed-to-detect alternative, the case-count grid 32, 62, 92, 120, 164 maps to cumulative person-time E = 1,270, 2,460, 3,650, 4,760, 6,510 per arm. We assign independent Gamma(1, 1) priors on both λc and λt, a single-criterion efficacy rule ℙ(log Δ < log 0.70 | ·) > 0.99 on the log-rate-ratio scale (the protocol superiority criterion against VE > 30%) and a futility rule ℙ(log Δ > log 0.70 | ·) > 0.90.

The gamma–Poisson conjugate update in adabay reduces the posterior tail probability to a beta cumulative distribution function (Appendix B of the manuscript), so no quadrature is required and the per-trial cost is dominated by the count-data simulator.

adabay call sequence

Design, prior and decision rule

library(adabay)

des <- set_design(endpoint         = "count",
                  exposure_per_look = c(2540, 4920, 7300, 9520, 13020),
                  effect_scale     = "log_rate_ratio",
                  alternative      = "less",
                  delta_null       = log(0.70))

pri <- set_prior(endpoint = "count",
                 arms = list(c = list(family = "gamma", a = 1, b = 1),
                             t = list(family = "gamma", a = 1, b = 1)))

dec <- set_decision(
  efficacy = list(list(threshold_effect = log(0.70), threshold_prob = 0.99)),
  futility = list(list(threshold_effect = log(0.70), threshold_prob = 0.90)),
  futility_binding = TRUE)

oc_h0 <- evaluate_design(des, pri, dec,
                         effect   = list(lambda_c = 0.018, lambda_t = 0.0126),
                         n_trials = 1e6, cores = 8, seed = 1L)
oc_h1 <- evaluate_design(des, pri, dec,
                         effect   = list(lambda_c = 0.018, lambda_t = 0.0072),
                         n_trials = 1e6, cores = 8, seed = 1L)

The H0 scenario fixes the rate ratio at the superiority threshold (Δ* = 0.70, VE = 30%), so the type I error rate reported under this scenario is the rate at which the design declares VE > 30% when in fact VE = 30%. The H1 scenario uses the designed-to-detect alternative (Δ* = 0.40, VE = 60%). The actual trial observed an outcome far inside the rejection region (eight vaccine cases versus 162 placebo cases at the final analysis, VE = 95.0%) and crossed the protocol superiority boundary at the fourth interim.

Operating characteristics

At R = 106 virtual trials per scenario the re-design reaches a type I error rate of 2.90% and a power of 87.68%, with an expected cumulative person-time of 7,662 person-years across both arms under H1 (versus the fixed-sample maximum of 13,020).

adabay runs on 8 CPU cores via mclapply with the L'Ecuyer combined multiple-recursive generator (cores = 8); BATSS with 8 mclapply workers and INLA pinned to one thread per worker. The BATSS comparison sets batss.glm's effect margin to log(0.70) with the null at the protocol rate ratio 0.70, and agrees with adabay within Monte Carlo error on type I error and power (under a residual person-time proxy that maps BATSS's recruited-patient interims onto the exposure-driven look schedule). Priors are independent Gamma(1, 1) in each arm for adabay, whereas BATSS uses its default INLA fit with weakly informative Gaussian priors on the log-rate regression coefficients. “n/a” marks comparators that do not support count endpoints (adaptr covers only continuous and binary outcomes; gsbDesign is restricted to the normal–normal continuous setting). The fixed-sample maximum is 13,020 person-years across both arms. Type I error is evaluated at λt / λc = 0.70 (the protocol superiority threshold, VE = 30%) and power at λt / λc = 0.40 (the designed-to-detect alternative, VE = 60%).

Dependencies. The comparator snippets below are not part of adabay and are not run by it. Reproducing them requires BATSS, which in turn requires INLA, to be installed; the adabay code on this page needs no additional packages.

BATSS

## BATSS comparator (matched budget R = 10,000, 8 mclapply workers).
## Attached, not just namespace-qualified: batss.glm() takes BATSS's bare
## helpers (alloc.balanced, eff.arm.simple, ...), which need it on the path.
library(BATSS)
INLA::inla.setOption(num.threads = "1:1")
RNGkind("L'Ecuyer-CMRG"); set.seed(1L)

## adabay judges both hypotheses against the protocol margin log(0.70), so the
## null must be simulated AT the margin (rate ratio 0.70) rather than at BATSS's
## automatic ratio-1 null: H0 = FALSE, and each truth is its own call.
## batss.glm takes N and the interims as TOTALS across both arms, so the adabay
## per-arm person-time schedule c(1270, 2460, 3650, 4760, 6510) is doubled here.
run_one <- function(beta_eff) BATSS::batss.glm(
  model       = y ~ group,
  var         = list(y = rpois, group = alloc.balanced),
  var.control = list(),
  family      = "poisson", link = "log",
  beta        = c(log(0.018), beta_eff),
  which       = 2, alternative = "less",
  R           = 10000, N = 13020,
  interim     = list(recruited = c(2540, 4920, 7300, 9520)),
  prob0       = c(control = 0.5, treatment = 0.5),
  delta.eff   = log(0.70), delta.fut = log(0.70),
  eff.arm     = eff.arm.simple, eff.arm.control = list(b = 0.99),
  fut.arm     = fut.arm.simple, fut.arm.control = list(b = 0.10),
  eff.trial   = eff.trial.all,  fut.trial = fut.trial.all,
  H0          = FALSE,
  computation = "parallel", mc.cores = 8)

r_typeI <- run_one(log(0.70))    # truth at the margin      -> type I
r_power <- run_one(log(0.40))    # truth at the alternative -> power

mean(r_typeI$H1$sample$type == "1")                              # type I error rate
mean(r_power$H1$sample$type == "1")                              # power
mean(r_typeI$H1$sample$control + r_typeI$H1$sample$treatment)    # E(E) | H0
mean(r_power$H1$sample$control + r_power$H1$sample$treatment)    # E(E) | H1

What this exercises

  • The gamma–Poisson conjugate update on the log-rate-ratio scale; closed-form posterior tail probability via a beta CDF.
  • Cumulative-exposure look schedules via the exposure_per_look argument of set_design().
  • A non-zero null on the log-rate-ratio scale via delta_null = log(0.70) and matching threshold_effect = log(0.70) in set_decision().
Reproduce. The full script is shipped with the package as inst/examples/bnt162b2.R.
