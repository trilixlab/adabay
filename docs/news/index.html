Changelog

Release notes for adabay.

adabay 0.1.0 2026-07-28

Initial public release accompanying the manuscript “adabay: an R package for rapid evaluation and calibration of Bayesian group sequential designs across common endpoint types”.

Public API

  • Four endpoint families: continuous (normal–normal or normal–inverse-gamma), binary (beta–binomial), count (gamma–Poisson) and time-to-event (gamma–exponential).
  • Constructors: set_design(), set_prior(), set_decision(), set_accrual().
  • Non-conjugate prior workflow: fit_mixture() approximates a user-specified prior by a finite mixture of conjugate components with per-quantile tail-probability diagnostics; returns a adabay_prior_arm object that plugs into set_prior() via its arms argument.
  • Entry points: evaluate_design() is the single polymorphic entry point for obtaining operating characteristics. Passing a adabay_design runs the fused simulate-and-aggregate path for a one-off single-design evaluation; passing a adabay_cache (built once by build_cache()) aggregates pre-computed per-look tail probabilities cheaply. calibrate_design() sweeps a threshold grid against the cached path for the caching API of Section 6 of the manuscript; summarise_oc() tidies the results across designs.
  • Methods: print() for all nine S3 classes — adabay_design, adabay_prior, adabay_prior_arm, adabay_decision, adabay_accrual, adabay_cache, adabay_calibration, adabay_calibration_best and adabay_oc; summary() for adabay_oc only; plot() for adabay_oc (per-look stopping-probability bar chart) and adabay_prior_arm (density overlay with tail-quantile rugs).

Implementation

  • C++ hot paths via Rcpp: the time-to-event trial simulator and a fixed 64-node Gauss–Legendre quadrature for the binary and count rate-difference tails of Δ. The remaining simulation loops, conjugate updates and mixture reweighting are in R.
  • Parallel execution via parallel::mclapply on POSIX and parallel::parLapply on Windows, with the L'Ecuyer combined multiple-recursive generator for per-worker streams.
  • Within-cores bit-identical reproducibility at any fixed (seed, cores) pair, and cross-cores bit-identical reproducibility via the cross_core_reproducible = TRUE argument on evaluate_design() and build_cache(), which forces the simulator pass to run in a single driver process irrespective of cores. Default FALSE preserves the parallel simulator path; set TRUE for regulatory submissions or other settings where reproducibility across hardware configurations is required.

Performance

Benchmarked against BATSS and adaptr at matched R = 10,000 simulation budgets on the binary ADRENAL re-design (Section 7.4 of the manuscript): per-virtual-trial speedups of approximately 39× versus adaptr (between one and two orders of magnitude) and 2.0 × 104 × versus BATSS (four orders of magnitude) on the binary case, with all three packages running on 8 cores at the matched budget. At R = 106, adabay completes the paired scenarios in roughly 5–138 seconds on 8 cores across the four endpoints, with Monte Carlo standard errors of 0.02–0.04 percentage points on the type I error rate and the power.

Documentation and scripts

  • Three knitr vignettes: overview (guided tour of the API), evaluation (conjugate and non-conjugate prior workflows) and calibration (end-to-end threshold calibration over a cache).
  • Four reproducible case-study scripts in inst/examples/ reproducing Section 5 of the manuscript:
    • transform2.R — TRANSFORM-2 esketamine re-design (continuous).
    • adrenal.R — ADRENAL hydrocortisone re-design (binary).
    • bnt162b2.R — BNT162b2 vaccine re-design (count).
    • checkmate141.R — CheckMate-141 nivolumab re-design (time-to-event).

Dependencies

  • Depends on R ≥ 4.0.
  • Imports Rcpp (≥ 1.0.7), parallel, stats and graphics.
  • Suggests RBesT, ggplot2, ggsci, testthat, knitr and rmarkdown.

Known limitations

  • Two-arm fixed-allocation designs only. Response-adaptive randomisation, sample-size re-estimation, covariate adjustment, multi-arm and platform designs, and arm-dropping are not implemented in this release.
  • The exponential survival model assumes a constant hazard within arms.
  • Forward-KL mixture fitting is mass-covering; tail accuracy must be checked using the diagnostics returned by fit_mixture().
