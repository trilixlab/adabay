evaluate_design()

Evaluate operating characteristics for a Bayesian group sequential design.

Description

evaluate_design() is the single entry point for obtaining the operating characteristics of a Bayesian group sequential design. It is polymorphic in its first argument:

  • Fused path (adabay_design as x): simulates n_trials virtual trials at the supplied data-generating values, computes per-look posterior tail probabilities of Δ in closed form, and applies the supplied decision rule to obtain the per-look stopping probabilities, the overall type I error rate (or power under the alternative), and the expected sample size, all in one call. Use this for one-off evaluation of a single design.
  • Cached path (adabay_cache as x): looks up pre-computed per-look tail probabilities in a cache produced once by build_cache() and aggregates them under the supplied decision rule, without re-simulating trials. Use this for grid-style calibration when many decision rules share the same simulated trials.
Usage
evaluate_design(x, ...)

# Fused path: x is a adabay_design
evaluate_design(
  x,
  prior,
  decision,
  effect,
  accrual  = NULL,
  n_trials = 10000L,
  cores    = 1L,
  seed     = NULL,
  cross_core_reproducible = FALSE,
  ...
)

# Cached path: x is a adabay_cache from build_cache()
evaluate_design(x, decision, look_subset = NULL, ...)
Arguments
x
A adabay_design object (fused path) or a adabay_cache object (cached path).
prior
For the fused path only: a adabay_prior from set_prior().
decision
A adabay_decision from set_decision().
effect
For the fused path only: named list of data-generating values; see the worked examples in the package vignettes for endpoint-specific names.
accrual
For the fused path only: a set_accrual() specification. Required for time-to-event designs, which are always staggered (the recruitment rate drives the calendar-time exposure cutoff); optional for the other endpoints, where it is used only to report the expected calendar duration.
n_trials
For the fused path only: number of virtual trials.
cores
For the fused path only: number of CPU cores. Defaults to 1.
seed
For the fused path only: optional integer seed.
cross_core_reproducible
For the fused path only: logical, default FALSE. When TRUE, the simulator pass is forced into a single driver process so the trial-level RNG draws are bit-identical across worker counts (intended for regulatory submissions); the default FALSE retains full simulator parallelism.
look_subset
For the cached path only: optional integer vector of look indices, selecting a subset of the cached looks (so that a single cache built over the full union of candidate look times can serve any look-time subset).
...
Further arguments passed to methods (currently unused).
Value

An object of class "adabay_oc" carrying the per-look stopping probabilities, the overall type I error and power, the expected sample size and (when an accrual specification is supplied) the expected calendar duration.

Examples
## Fused path: evaluate a single design directly
oc <- evaluate_design(des, prior = pri, decision = dec,
                      effect   = list(theta_c = 0.33, theta_t = 0.28),
                      n_trials = 200L, cores = 1L, seed = 1L)
print(oc)

## Cached path: build once, evaluate many decision rules cheaply
cache <- build_cache(des, pri,
                     effect         = list(theta_c = 0.33, theta_t = 0.28),
                     n_trials       = 200L,
                     seed           = 1L,
                     threshold_grid = list(efficacy = 0, futility = 0))
oc2 <- evaluate_design(cache, dec)
print(oc2)

## Cached path with look_subset: three-look design from the same five-look cache
oc_3look <- evaluate_design(cache, decision = dec, look_subset = c(2, 4, 5))
